# ARS 메뉴 선택 평가 결과 (gemini-3.5-flash-lite)

Notion '02 ARS 통화·메뉴 수집'의 ARS 원문으로, Gemini 가 여러 가지 요청에 맞는 메뉴 번호를 고르는지 확인했다.

- 데이터: `ars_menu_cases.py` — 10개 기관, 버튼 메뉴 50개, 요청 254개
  - 요청 종류: 명확한 요청, 구어체, 애매한 요청(정답: 누르지 않고 묻기), 맞는 메뉴 없음, 같은 번호가 두 번 들린 원문
  - 제외: 코레일(버튼이 아닌 음성 대화형 ARS)
- 도구: `confidence_eval.py` (`collect` 측정, `report` 기관별 결과, `sweep` 확신도 기준 비교)
- 판단 규칙: 서버(navigator)와 같다. 1위 0.50 이상·1·2위 차이 0.10 이상이면 누름, 0.30~0.50 재질문, 0.30 미만 누르지 않음
- 측정: 2026-10-27, 생각 수준 MINIMAL, 판단 대기 20초. 원자료 `docs/evals/menu_eval_2026-10-27_before_fix.json`

## 확신도 기준 (Go/No-Go)

1위 확신도 구간별로 1위가 정답인 비율 (정답 있는 요청 178개)

| 1위 확신도 | 건수 | 1위가 정답 |
| --- | --- | --- |
| 0.9~1.0 | 154 | 100% |
| 0.8~0.9 | 11 | 100% |
| 0.7~0.8 | 2 | 100% |
| 0.6~0.7 | 7 | 71% |
| 0.5~0.6 | 1 | 100% |
| 0.3 미만 | 3 | 33% |

'누르면 안 되는' 요청 22개 중 13개도 1위가 0.5 이상이었다. 확신도만으로는 애매한 요청을 거르지 못하고 1·2위 차이가 함께 필요하다.

| Go 기준 | 1·2위 차이 | 틀리게 누름 | 정답 있는 요청 중 바로 해결 |
| --- | --- | --- | --- |
| 0.50 (현재) | 0.1 (현재) | 8 | 94% |
| 0.50 | 0.2 | 6 | 94% |
| 0.60 | 0.2 | 5 | 94% |
| **0.70** | **0.2** | **2** | **92%** |
| 0.70 | 0.3 | 1 | 90% |
| 0.80 | 0.2 | 2 | 91% |
| 0.90 | 0.2 | 1 | 85% |
| 0.95 | 0.2 | 1 | 55% |

제안 (서버 `config.py` 기준값, 준성님과 결정)
- Go: 1위 0.70 이상, 1·2위 차이 0.20 이상. 틀린 누름 8 → 2건, 바로 해결은 94% → 92%
- 0.70 미만은 재질문. 0.6~0.7 구간 정답률이 71%(7건 중 5건)라, 틀려도 이전 단계로 돌아올 수 있는 메뉴에서 '먼저 눌러 보고 돌아오기'를 할 만한지 판단하기에는 아직 표본이 적다
- 서버 비교식 주의: 0.95 − 0.85 처럼 차이가 정확히 0.10 인 경우 부동소수점 때문에 0.0999… 로 계산되어 재질문으로 간다 ("국민연금 고지서", "택배 조회" 사례). `navigator.py` 의 차이 비교에 작은 오차 허용(예: `>= margin - 1e-9`)을 두는 것을 제안
