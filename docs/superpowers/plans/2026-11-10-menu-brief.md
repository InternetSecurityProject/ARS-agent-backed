# Caption more — local implementation

**Goal:** 별도 메뉴 요약 대신 같은 ARS 안내문을 3줄 미리보기 → 더보기 → 접기로 표시한다.
**Architecture:** 기존 공통 CaptionDisclosure와 통화 단위 captionOpen 상태를 재사용한다. 최신 서버 text와 데모 안내문을 그대로 표시하고 CSS로 실제 3줄만 접는다. 이전 receivedMenuOptions 표시 모델·props·별도 메뉴 목록은 제거한다.
**Spec:** 사용자가 ‘받은 메뉴’·‘ARS 선택지’ 구분과 요약/전체 내용 차이를 지적하여 더보기 방식으로 변경 승인. 추가 AI·백엔드/API/음성 변경·실제 발신·푸시·머지 없음.

## Decisions
- ‘ARS 안내’ 앞부분과 펼친 전문은 같은 문자열·같은 DOM 요소다. 문장을 다시 쓰거나 메뉴를 추출하지 않는다.
- 접힌 더보기 버튼은 미리보기 아래, 펼친 접기 버튼은 전문 위. keyed 순서 변경으로 키보드 포커스를 유지한다.
- 최근 선택·ARS 안내 간격(20/23px), 새 질문 스크롤 수정, 후보 선택 기능·중요 입력·결과는 유지한다.
- 안내 길이·화면 폭·글씨 크기·폰트 변화 시 기존 3줄 판단을 재측정한다. 짧은 안내에는 더보기를 만들지 않는다.
- 서버 수신 text 자체는 메뉴 목록으로 압축되었을 수 있다. 별도 STT 원본 복원은 아니다.
- 데모는 같은 안내문/공통 표시를 사용하고 더보기를 확인할 수 있는 긴 날씨 안내를 제공한다.

## Verification ledger
- RED: 기존 동일 단계 메뉴 데이터가 있는 화면에 ‘받은 메뉴’가 남아 있어 두 폭에서 새 기대와 다름을 확인.
- 구현: 별도 메뉴 요약과 연결 표시 모델 제거, 더보기/접기 문구 적용, 기존 CSS 미리보기·전문 보존·포커스 유지.
- 관련 첫 실행에서 짧은 데모 안내가 실제 3줄 안에 들어 더보기 없는 정상 동작을 확인. 길게 확인 가능한 데모 안내 예시로 보완.
- 전체 웹 테스트 58개 통과. 실제 폰트로 기본·큰글씨·데모·새 질문 스크롤·키보드 포커스·결과/입력 검증. 원본/생성물 일치 및 diff --check 통과.
- 8014 예시 갱신 후 3줄 미리보기 → 전체 10줄 → 다시 접기와 동일 문자열 보존 확인, 브라우저 오류 없음. 원본/생성물은 재빌드하여 제공, 커밋·푸시·머지 없음.

- 후속 디자인 요청: 안내가 이어지는 느낌을 위해 전사문 토글의 회색 배경을 제거하고 텍스트 뒤에 얇은 위/아래 화살표를 배치. 더보기는 본문 아래 4px, 접기는 전사문 위 오른쪽. 최소 터치 영역과 원문/행수/펼침/포커스 유지. 관련 기존 테스트 36개·로컬 예시 전후 캡처·생성물 일치·diff 확인 통과.

- 최신 후속 요청: 대기 배지는 전 화면에서 제거하되 응답 가능한 질문·입력 배지는 유지. 펼친 접기를 ARS 안내와 같은 grid 행 오른쪽으로 배치하여 별도 버튼 행 공백 제거. DOM/키보드 순서·포커스·44px 터치 높이 유지. RED에서 대기 배지 잔존·두 줄 헤더 실패 확인 후 관련 36개·전체 웹 58개 통과, 8014 화면 캡처·재빌드 일치·diff 확인 통과. 로컬 변경만 유지.

- 2026-11-11 통합 승인: 사용자가 최종 로컬 화면 확인 후 feat/model-select-concurrent-calls로 머지·푸시 요청. 이전 로컬 전용 제한은 구현 단계의 기록이며 이번 통합 승인이 우선한다. main·실제 서버 배포는 제외.
