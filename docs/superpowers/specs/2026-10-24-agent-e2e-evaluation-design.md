# ARS 에이전트 전체 세션 평가 설계

## 의도

사용자의 모호한 일상 표현을 업무 목표로 정리하고, 필요한 경우 확인 대화를 거친 뒤, 여러 단계의 전화 안내 메뉴를 탐색해 건강보험증 발급 결과까지 도달하는지를 검증한다. 기존 한 단계 메뉴 선택 평가는 회귀 테스트로 유지하되 전체 세션 성공률을 모델 선정의 주 지표로 바꾼다.

## 범위

- 기관과 업무: 국민건강보험공단 건강보험증 발급
- 사용자 대화: 직접 표현, 모호한 표현, 오타·STT 오류, 정정, 복수 요청, 취소, 비대상 요청
- 전화 안내 흐름: 메인 메뉴, 민감정보 직접 입력, 입력값 확인, 발급 동의, 배송지 선택, 완료 감지
- 비교 모델: `gemini-3.5-flash-lite`, `gemini-3.5-flash`
- 실제 음성 STT, 전화 연결, 실제 DTMF 전송은 이번 평가에서 제외

## 평가 방식

각 시나리오는 사용자 대화와 전화 안내 흐름으로 구성한다. 모델은 사용자 대화마다 정규화된 의도와 다음 행동을 구조화해 반환하고, 업무가 확정되면 전화 안내 문장마다 다음 행동을 반환한다. 이전 모델 응답을 다음 턴의 대화 이력에 포함해 문맥 유지 능력도 검증한다.

전체 세션 성공은 다음 조건을 모두 만족할 때만 인정한다.

- 최종 업무 의도와 배송지 조건이 기대값과 일치한다.
- 확인·추가 질문·취소·통화 시작 행동이 각 턴의 기대값과 일치한다.
- 기대한 DTMF 경로를 순서대로 선택한다.
- 주민등록번호 입력에서 AI가 중단하고 사용자에게 제어권을 넘긴다.
- 사용자의 확인 답변을 반영해 탐색을 재개한다.
- 발급 완료 안내를 업무 완료로 인식한다.
- 존재하지 않는 번호 추측이나 민감정보 자동입력이 한 건도 없다.

## 접근 방식

1. 한 번의 프롬프트로 전체 미래 대화를 제시하는 방식은 싸고 빠르지만 실제 상호작용과 다르므로 제외한다.
2. 의도 분석과 메뉴 판단을 별도 벤치마크로만 측정하는 방식은 실패 위치를 찾기 쉽지만 세션 문맥 손실을 잡지 못하므로 보조 지표로만 사용한다.
3. 선택 방식: 실제 순서대로 모델을 반복 호출하는 시뮬레이터를 사용한다. 비용과 시간이 더 들지만 제품 동작과 가장 가깝고 전체 업무 완료율을 직접 계산할 수 있다.

## 산출물

- 전체 세션 시나리오 데이터셋
- 사용자 목적 분석용 구조화 프롬프트와 스키마
- 반복 호출 시뮬레이터와 자동 채점기
- 모델별 세션 성공률, 단계별 정확도, 위험 행동, 지연, 호출 오류 보고서
