# 웹 화면 개발

기존 Preact + htm 구조를 유지한다. `app.src.html`이 원본이며 `static/app.html`을 직접 편집하지 않는다.

```sh
cd web
npm ci
npm run build -- ../../ARS-agent-frontend/app/src/main/assets/figma ../static/app.html
npm run preview
```

빌드 첫 인자는 기존 Android 리포의 SVG 아이콘 폴더다. 다른 위치에 체크아웃했다면 그 경로를 지정한다.
기존 `python web/build.py <아이콘 폴더> static/app.html` 명령과 `web/vendor` 방식도 유지한다.

## 로컬 확인

`http://127.0.0.1:8013/app`을 연다. 상단 오른쪽 **큰글씨 보기**를 누르면 안내·선택지·입력·버튼 설명이 25% 확대된다. 같은 버튼으로 기본 크기를 복원한다. 전화번호·키패드 숫자·아이콘 크기는 유지한다. 이 설정만 브라우저에 보관하며 저장소가 막혀 있어도 현재 화면의 전환은 가능하다.

상단 **실제 ARS → UI 데모** 또는 **후보 선택 / 민감정보 입력**을 선택한 다음 131을 입력하고 **ARS Agent 전화**로 데모에 들어간다. 목적을 입력하면 기존 데모 순서로 진행한다.

UI 데모의 Agent 통화 중에는 네 번째 원형 **상담원 연결** 버튼을 사용할 수 있다. 기존 업무 목적을 확인·수정한 뒤 **상담원 연결 요청**을 누르면 탐색 예시에서 상담원 대기로 진행한다. 입력 중 데모 자동 진행은 멈추고 **돌아가기**로 기존 단계에 복귀한다. 마이크는 녹음 대신 예시 업무 문장을 채운다. 연결 중·개인정보 입력·상담원 대기에는 다시 요청하지 못한다. 실제 서버 통화 화면에는 아직 추가하지 않았다.

이 미리보기 서버는 정적 화면만 제공하고 모든 API를 403으로 차단한다. 실제 발신·마이크 테스트·서버 연동용이 아니다. 기존 8011 서버나 배포 서버를 재시작하지 않는다. UI 확인 뒤 서버 연동 검증은 별도 승인 범위에서 진행한다.

Agent 통화 화면에는 전화번호·기관명·연결 상태 또는 통화 시간을 표시한다. 발신 전 목적 입력 화면에도 기관명을 표시한다. 기본 글씨에서는 번호 아래에 기관명과 시간을 함께 표시한다. 큰글씨 Agent 화면은 번호와 시간을 나란히 배치하고 기관명은 그 아래 별도 줄에 표시한다. 번호와 시간이 한 줄에 들어가지 않으면 자동 줄바꿈한다. 큰글씨에서도 통화 종료가 확인된 화면은 일반 종료 화면처럼 번호 아래에 종료 상태·통화 시간을 가운데 정렬하고, 글씨 확대는 유지한다. `010-5555-5555`와 `1588-9999`는 기본·큰글씨 모드에서 잘림 없이 표시되는지 확인했다. 상하·좌우 여백을 줄인 공간은 정보 카드에 사용하며 원형 버튼 크기는 유지한다.

메뉴 탐색 중에는 ‘원하는 메뉴를 찾고 있어요’를 표시하며 별도 ‘기다려 주세요’ 배지는 표시하지 않는다. 응답이 필요하면 질문 원문을 제목으로 표시하고 응답 가능한 카드에만 파란 테두리를 붙인다. 새 질문은 한 번만 짧게 강조하며 모션 감소 설정에서는 움직이지 않는다. 전송·만료·연결 불가 시 강조를 해제한다. 개인정보 키패드는 카드 밖 배치를 유지한다. 큰글씨 전환과 같은 질문의 기한 연장 시 작성 중인 답변은 유지하며, 질문 변경·만료·응답 불가 시 초기화한다. 기존 질문 음성과 개인정보 음성 제한을 재사용한다.

새 질문이 도착하면 이전 안내를 읽던 스크롤을 상단으로 맞춘다. 화면 높이에 따라 카드 또는 바깥 읽기 영역에 적용하며, 같은 질문의 안내·기한 갱신과 글씨 크기 전환에는 스크롤을 초기화하지 않는다. 입력칸으로 포커스를 강제 이동하지 않는다. 카드의 파란 소제목은 진한 파란색을 사용하며 흰 배경과 약 6.24:1의 대비를 확보한다. 데모와 큰글씨에도 동일하게 적용한다.

후보 선택 버튼의 글씨는 기본 16px·큰글씨 20px이며 최소 높이는 각각 56px·70px이다. 서버가 보낸 메뉴 문구와 선택 키는 유지하고, 긴 문구는 줄바꿈하며 버튼 높이를 늘린다. 번호와 `*`·`#`는 오른쪽 칸으로 구분한다. 후보 간격은 10px이며 많은 후보는 카드 안에서 스크롤해 확인한다. 말하기·글자 입력은 후보 아래, 하단 원형 버튼은 기존 위치를 유지한다.

일반 진행 화면에서는 ‘지나온 메뉴 보기’ 토글과 현재 진행 제목을 순서대로 표시한다. 최근 선택한 메뉴는 펼쳐두고, 한 단계뿐인 경로에는 접기 버튼을 만들지 않는다.

‘ARS 안내’는 별도 요약이나 선택지 목록으로 바꾸지 않는다. 긴 수신 안내문의 앞부분을 실제 표시 3줄까지 보여주고 ‘더보기’로 같은 문장 전체를 펼친다. 회색 박스 없이 본문 아래에 텍스트형 ‘더보기⌄’를 붙인다. 펼친 ‘접기⌃’는 ‘ARS 안내’ 제목과 같은 줄 오른쪽에 두어 본문 위 여백을 줄이고, 두 조작 모두 최소 44×44px 영역과 키보드 포커스를 유지한다. 최근 선택과 안내문 사이 간격은 기본 20px·큰글씨 23px다. 짧은 안내와 결과 안내에는 더보기를 만들지 않으며 질문·개인정보·결과 요약·오류는 기존 우선 표시를 유지한다. 펼침 설정은 현재 통화 동안 안내 갱신·큰글씨·입력 화면 전환에도 유지하고 새 통화에서 초기화한다. 데모도 같은 표시 컴포넌트를 사용한다.

표시는 서버가 보낸 text 그대로이며 추가 AI 호출·프론트 요약·메뉴 번호 추출을 하지 않는다. 서버가 이미 text를 메뉴 목록으로 압축했을 수도 있으므로 별도 STT 원본 복원이라고 설명하지 않는다.

## 검증

```sh
npx playwright install chromium
npm test
```

이미 설치된 Chromium을 쓰려면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`를 실행 파일 경로로 설정한다. 테스트는 임시 로컬 서버를 사용하며 외부 요청·서버 API를 차단한다.

실제 폰트의 줄바꿈까지 검증하려면 `WEB_TEST_NOTO_FONT`와 `WEB_TEST_GOWUN_FONT`를 각각 로컬 Noto Sans KR·Gowun Batang TTF 경로로 설정한다. 테스트 서버가 이 파일만 로컬에서 제공하므로 외부 폰트 서버나 실제 API에 연결하지 않는다. Android 리포의 `app/src/main/res/font/` 파일을 사용할 수 있다.

## 동시 작업

작업 기준은 `feat/model-select-concurrent-calls`이다. 스타일 변경은 의미별 CSS custom property, 동작은 `useTextSizePreference` / `TextSizeControl`에 모은다. 화면·세션 컴포넌트에 설정을 위한 key를 추가하거나 재생성하지 않는다.

공유 전 기준 브랜치를 fetch하고 원본에서 충돌을 해결한 뒤 생성물을 다시 빌드한다. 생성된 `static/app.html`만 덮어쓰거나 배포 서버 파일을 복사해 원본을 대체하지 않는다. 서버에 미푸시 변경이 있으면 배포 담당자와 원본부터 맞춘다.
